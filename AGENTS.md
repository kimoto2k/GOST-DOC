# AGENTS.md — правила для Codex в GOST DOC

## Язык и цель
- Общайся с владельцем проекта по-русски, код и тесты могут быть на английском.
- GOST DOC — приложение Python/Streamlit для загрузки, диагностики и оформления .docx. Исходный код в этом репозитории является источником истины.
- Для истории решений, точного задания и этапов разработки сперва прочитай `docs/PROJECT_HANDOFF.md`, `docs/MISIS_RULES.md` и `docs/NEXT_STEPS.md`.
- Принятые UX-принципы: минималистичный аккуратный дизайн, русскоязычный интерфейс, понятная последовательность «загрузка → проверка → исправление → скачивание», мобильная адаптивность.

## Архитектура
- `app.py` — интерфейс Streamlit.
- `gostdoc/formatter.py` — преобразование DOCX. Не смешивай здесь UI и бизнес-логику.
- `gostdoc/workflow.py` — диагностика, профили JSON, экспорт ZIP/CSV, демо.
- `tests/` — pytest.
- `.streamlit/config.toml` — цветовая тема.
- `README.md`, `CONTRIBUTING.md`, `SECURITY.md` — эксплуатация, командная работа, безопасность.

## Нормативные настройки
- Различай *ГОСТ 7.32–2017* и методические указания МИСИС для учебных работ: это не одно и то же.
- Правила для режима «МИСИС» см. в `docs/MISIS_RULES.md`, составленном по переданному пользователем 15-страничному PDF. Пока полный PDF не внесён в репозиторий; не утверждай, что видел оригинал макета титульного листа в кодовой среде.
- Текущий основной профиль: Times New Roman 12 пт, A4, интервал 1.5, красная строка 1.25 см, поля 30/15/20/20 мм. У МИСИС таблицы отличаются: 10 пт, интервал 1.0, выравнивание слева.
- Не выдавай автоматическую техническую проверку за полное соответствие ГОСТ/методичке. Проверяй ручные и неавтоматизируемые требования честно.

## Безопасность и сохранность документов
- Не удаляй текст, таблицы, формулы, сноски, разрывы, изображения, ссылки и содержимое колонтитулов без явного требования. Предпочитай минимально инвазивные операции с DOCX.
- Не допускай передачи секретов или персональных данных пользователей в репозиторий и логи.
- В публичном Streamlit документы обрабатываются на сервере хостинга, а не локально. Обязательно объясняй пользователям этот факт.
- Для загруженных ZIP/DOCX сохраняй ограничения на размер файла и разархивированный объём, проверяй повреждённые файлы.
- Импорт профилей JSON валидируй. Для ZIP экспорта чисти имена файлов от путей и опасных символов.

## Процесс разработки
1. Сначала изучи существующий код, тесты и выбранный scope; затем сформируй короткий план.
2. Делай изменения в ветке `feature/...`, открывай Pull Request в `main`, если не получено отдельное указание.
3. Запускай `python -m pytest -q`, `python -m compileall -q app.py gostdoc` и тест запуска Streamlit.
4. Если меняешь форматирование Word, добавляй регрессионные тесты, которые открывают созданный DOCX и сравнивают ожидаемые стили/структуру.
5. Не меняй формат источника без решения пользователя; PDF и DOC старого формата — отдельные задачи, основной формат .docx.
6. Не заявляй визуальную проверку страниц без настоящего рендера Word/PDF.
7. В итоговом отчёте перечисляй изменённые файлы, проверки и оставшиеся ограничения.
